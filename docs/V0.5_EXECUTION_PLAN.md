# Agent Nudge v0.5 Execution Plan

## Release outcome

A clean Windows user can download Agent Nudge, verify the artifact, install it, connect a supported provider after reviewing an exact dry-run, execute an isolated two-agent proof, and inspect a valid receipt without developer assistance.

## Non-goals

- cloud synchronisation;
- billing or accounts;
- transcript capture;
- unrestricted remote APIs;
- enterprise SSO;
- autonomous merging;
- hidden provider mutation.

## Workstream A: reliability and storage

- [ ] Resolve one canonical Agent Nudge data directory.
- [ ] Make the daemon the sole SQLite writer.
- [ ] Route Electron, CLI, MCP, and hooks through the daemon or outbox.
- [ ] Add SQLite busy timeout.
- [ ] Wrap every multi-record protocol operation in a transaction.
- [ ] Enforce active-claim uniqueness by project and normalised path.
- [ ] Create an operation journal with planned, backed-up, applying, committed, rolling-back, rolled-back, and needs-recovery states.
- [ ] Inspect incomplete operations at startup.
- [ ] Recover only when ownership and hashes prove safety.
- [ ] Preserve external edits and surface ambiguous recovery.
- [ ] Add process-termination fault injection after every connector mutation phase.

## Workstream B: security and protocol

- [ ] Generate a random per-installation daemon secret.
- [ ] Store it outside repositories with owner-only permissions.
- [ ] Require authentication on every local API route except a minimal unauthenticated bootstrap if strictly necessary.
- [ ] Validate Host and Origin where applicable.
- [ ] Add authenticated health challenge and daemon instance ID.
- [ ] Support token rotation without logging the token.
- [ ] Create versioned endpoints for acknowledge, dismiss, snooze, wrong, stale, and used.
- [ ] Require project and recipient ownership for feedback transitions.
- [ ] Append feedback and protocol receipts in the same transaction.
- [ ] Define provenance levels: self-reported, hook-observed, command-receipt, test-verified, git-verified, human-confirmed, signed-remote.
- [ ] Complete `docs/THREAT_MODEL.md` and red-team fixtures.

## Metric definitions

Do not use `conflictsPrevented` as a synonym for delivered or acknowledged BLOCK nudges.

Track separately:

- conflict detected;
- warning generated;
- warning delivered;
- warning reviewed;
- warning acknowledged;
- action changed;
- path claim released;
- conflict prevented with evidence;
- false positive;
- false negative where observable;
- ignored or bypassed;
- preflight latency;
- repeated work avoided.

## Research outputs

Every research task must generate at least one implementation asset:

- typed schema;
- versioned fixture;
- conformance test;
- architecture decision record;
- benchmark dataset;
- threat-control test;
- prioritised issue with acceptance criteria.

Research targets:

- GitHub Copilot hooks;
- Cursor hooks;
- Gemini CLI hooks;
- Claude Code hooks;
- Codex project hooks;
- OpenCode plugins;
- Git worktree identity;
- OpenTelemetry-compatible privacy-safe traces;
- A2A-compatible read-only status exchange;
- persistent context poisoning and provenance controls.

## Completion gates

The release is not complete because the application compiles. It is complete only when all relevant checks pass and a clean Windows user reaches the first valid receipt without developer intervention.
